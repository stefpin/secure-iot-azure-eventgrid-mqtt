Behind the Scenes - what each Azure service does

Follow one real message through the platform and see the timestamp every Azure service gave it - from the machine to the operator app and Cosmos DB, and from the operator's click back to the machine. Nothing is simulated: the view only watches the app's own traffic.

The Behind the Scenes view is turned off on this server (IOT_TRACE=off). Everything else works as usual.

Follow one reading: — → Event Grid → Event Hubs (Kafka) → Cosmos DB

ready

Press Follow the next reading. The trace starts with the machine's next message (one every 5 seconds) and follows it on both paths: live over MQTT to this app, and routed by Event Grid to Event Hubs, read back over Kafka and stored in Cosmos DB. Each box turns green when that service has handled the message.

Show the message as each service saw it (MQTT payload → CloudEvent → Cosmos DB document)

Follow one command: browser → Front Door → app → Event Grid → — and back

ready

Press a speed button - or send a command from the Monitoring Dashboard and press Latest command. The click goes through Azure Front Door to the operator app, which publishes an MQTT 5 request to the machine's command topic; the machine answers on its response topic and republishes its retained state.

Device console: — its own log, fetched through the site gateway over MQTT

Press Refresh to load the last lines of the machine's log.

Times come from three clocks: the machine (vm-site1), Azure Event Grid and Event Hubs, and the operator VM (vm-ops). A step marked ≈ crosses from one clock to another - a few milliseconds of difference between clocks is normal.
